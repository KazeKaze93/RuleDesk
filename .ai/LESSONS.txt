RuleDesk Engineering Lessons (Canonical)
Format: Problem -> Root Cause -> Invariant Rule
Numbered entries keep their historical IDs (referenced elsewhere); new entries are titled under category headers. Operative rules (allowlists, ESLint configs) live in `.cursorrules` — entries here reference them, never copy them.

1) Hooks Order Violations
Problem: Runtime errors from conditional hook usage.
Root Cause: Hooks called inside JSX, branches, or loops.
Invariant Rule: Call hooks only at the top level of React components and custom hooks.

2) Filter Model Drift
Problem: UI pages break after filter schema changes.
Root Cause: Store contract changed but not all consumers were updated.
Invariant Rule: Any filter contract change requires synchronized updates across store, panels, and all feed pages.

3) Idempotent IPC Under Strict Mode
Problem: Duplicate startup calls trigger throttling and unstable UX; partial collapse keys leak wrong results across concurrent calls.
Root Cause: Idempotent handlers were treated like mutating ones, or collapse keys used only `id`/`type` and ignored other fields.
Invariant Rule: Mark truly idempotent handlers; collapse in-flight calls by hashing the full canonical args; space mutating calls with delay (never reject).

3a) Shared IPC Validation
Problem: Repeated ad-hoc Zod schemas diverge across handlers over time.
Root Cause: Contracts copy-pasted per handler instead of shared.
Invariant Rule: Extract shared Zod schemas into shared modules and reuse them across handlers.

3b) Type Assertion Policy
Problem: Project rules banned all `as` casts while the codebase kept assertions — the rule read as decorative when the gate only banned narrowing.
Root Cause: Policy text required a full allowlist gate, but CI only enforced unsafe narrowing; `// boundary:` comments without `eslint-disable` were not forced.
Invariant Rule: `as` is forbidden except `as const` and the closed boundary allowlist defined in `.cursorrules` (single source of truth — do not restate the list here). Every allowed assertion carries `// boundary: <reason>` + `eslint-disable-next-line` for every firing rule. Gate: `no-restricted-syntax` on `TSAsExpression` (excluding `as const`) plus `no-unsafe-type-assertion`. Fix types upstream or use Zod.parse — do not cast.

3c) Syntax Policy Inventory Must Use AST
Problem: Policy-violation counts from `grep`/`rg` for ` as ` were inflated by an order of magnitude and drove wrong "partial gate" conclusions.
Root Cause: Regex matches `import * as X`, SQL `AS alias`, and English prose, not TypeScript `TSAsExpression` nodes.
Invariant Rule: Inventory of syntactic constructs (type assertions, etc.) MUST use AST (ESLint selector / parser). Grep totals are not decision inputs.

4) Virtualized Gallery Holes
Problem: Large empty scroll area in filtered lists.
Root Cause: Virtualization total count used raw items while rendering filtered items.
Invariant Rule: Virtualization `totalCount` must always match the rendered collection length.

5) Retry and Timeout Leaks
Problem: Delayed callbacks run after unmount and create leaks.
Root Cause: Retry timers are created without cleanup paths.
Invariant Rule: Every timeout/interval created in effects must be cleared in cleanup.

6) Error Handler Infinite Loops
Problem: Image fallback logic loops forever on invalid fallback URLs.
Root Cause: Fallback retries do not track already-attempted URLs.
Invariant Rule: Error fallback logic must include a hard termination condition.

7) URL Extension Misdetection
Problem: Media type detection fails on URLs with query strings.
Root Cause: Extension checks run on full URL string.
Invariant Rule: Parse URL pathname first, then detect media extension.

8) Documentation Drift
Problem: Docs describe behavior that no longer matches implementation; hand-maintained IPC tables drift from controllers.
Root Cause: Code changes ship without synchronized documentation updates; large manual api.md cannot stay in sync with channels.ts.
Invariant Rule: Any behavior/API/workflow change must update `README.md`, `docs/*`, and lessons in the same task. The IPC channel reference (`docs/api.md`) is **generated** via `npm run docs:api` from `channels.ts` + handler registrations — hand-editing it is forbidden; regenerate after IPC changes and keep narrative in `docs/api-guide.md` / `docs/api-notes/`.

9) Unused Code Debt
Problem: Dead imports/variables increase noise and hide real issues.
Root Cause: Refactors are merged without cleanup.
Invariant Rule: Run `npm run validate` before finishing and remove all unused imports/variables.

## IPC & Errors

### Problem: Custom Error fields silently stripped across the IPC boundary
**Root Cause:** Electron `ipcMain.handle` / `ipcRenderer.invoke` serialize rejections through structured clone semantics — custom Error properties (`providerKind`, `kind`, `code`, `retryAfterMs`) are dropped; only `message` survives reliably. Mocked-IPC unit tests cannot see this: mocks pass objects by reference.
**Invariant Rule:** Typed error payloads crossing IPC must be JSON-encoded into `error.message` in Main, normalized in preload, and parsed in the shared layer (`provider-search-ipc.ts` pattern). Never rely on custom Error fields surviving `invoke`. Any branch changing IPC error shapes requires live Electron verification before merge (see `.cursorrules` — LIVE ELECTRON VERIFICATION).

### Problem: Provider errors returned as empty results create silent failure loops
**Root Cause:** Handlers returned `[]` on provider failure instead of throwing; the UI interpreted emptiness as "no data", retried, and amplified into a 429 storm.
**Invariant Rule:** Errors must surface, not swallow. On provider/IPC failure throw a typed error (`ProviderSearchError` with kind); never map failure to an empty-success shape. Rate-limit responses must propagate `retryAfterMs` and back off globally, not per-call.

## Data Integrity

### Problem: Sync cursor advanced past unfetched pages, permanently skipping posts
**Root Cause:** `lastPostId` was written in mid-batch and error-path commits while pagination was still in flight; a failure mid-pagination left older pages unfetched but below the new cursor — invisible, permanent data loss reported as "partial success". Closing SQLite in `before-quit` while sync still wrote compounded this (lost incomplete flag / FTS triggers dropped mid-initial-sync).
**Invariant Rule:** A pagination/sync cursor advances in exactly ONE code path, guarded by a completion flag that is set only at natural termination points at the END of a fully successful iteration (short page after commit; known-territory reached) — never at the top of the loop, never in catch. Incomplete runs must be persisted as visible state (`lastSyncIncomplete`) and must not update `lastChecked`. Completion flags set before the work they attest to are bugs waiting for an exception. App quit must `requestCancel` + drain in-flight sync before `closeDatabase`; hard-kill still requires restoring every runtime-dropped FTS trigger on DB init via one shared list (`ensureFtsTriggers`).

### Problem: FTS5 triggers declared ON virtual table never exist
**Root Cause:** Triggers were declared `AFTER … ON posts_fts`, but `posts_fts` is `CREATE VIRTUAL TABLE … USING fts5`. SQLite rejects that with `cannot create triggers on virtual tables`; the migration aborted at the first CREATE and soft-fail paths marked it executed anyway — stamp/count tables existed, triggers did not. Greenfield installs seeded `fts5_count_meta.count = 0` forever → smart tag playlists returned empty.
**Invariant Rule:** FTS5 external-content tables → SQLite forbids `CREATE TRIGGER ON` a virtual table; the migration aborts at that statement → Every trigger touching FTS must be declared ON the content table (`posts`). Before touching FTS, grep for `TRIGGER` + `ON <virtual table>` across `drizzle/` and `src/`.

### Problem: Swallowed DDL hides permanently missing schema objects
**Root Cause:** `try/catch` around `CREATE TRIGGER` / `CREATE TABLE` logged a warning and continued (or marked the migration executed). Runtime had no symptom until a feature depended on the missing object (empty smart playlists, stale count cache). Soft-fail branches that matched SQLite message substrings (`cannot create triggers on virtual tables`) turned one bad migration into a permanent factory for silent schema gaps.
**Invariant Rule:** A swallowed DDL error hides a permanently missing schema object with no runtime symptom → Never wrap `CREATE TRIGGER` / `CREATE TABLE` in try/catch. Let startup fail loudly. Matching DB errors by English message substrings is a dependency on an unstable format — prefer stable `error.code` / object-type checks; message includes are last-resort legacy only.

### Problem: FTS5 external-content DELETE trigger corrupts DB file
**Root Cause:** `DELETE FROM <fts_table> WHERE rowid=...` on an external-content FTS5 table bypasses the internal segment-delete protocol SQLite expects; observed as SqliteError `database disk image is malformed` / `SQLITE_CORRUPT_VTAB` on better-sqlite3 12.5.0 / SQLite 3.51.1 (msvc-1944), triggered by any `UPDATE OF <indexed column>` or `DELETE` on the content table, independent of mmap_size or batch size (single-row reproduces it). Separately: the canonical `VALUES('delete', ...)` command still corrupts if the rowid was never inserted into the index (e.g. insert trigger dropped for bulk upsert, then conflict UPDATE fires update trigger). And `id NOT IN (SELECT rowid FROM posts_fts)` never backfills missing index rows — without MATCH, a query on an external-content FTS5 table is passed through to the content table (fts5.html), so the NOT IN set is every posts.id.
**Invariant Rule:** External-content FTS5 tables (`content='...'`) must use the canonical `INSERT INTO <fts>(<fts>, rowid, ...) VALUES('delete', ...)` command to remove indexed rows, never `DELETE FROM <fts_table>`. Never issue that `'delete'` command for a rowid that was not previously inserted into the index — when bulk-dropping `posts_fts_insert`, also drop `posts_fts_update` for the same window, then backfill with `INSERT INTO posts_fts(rowid, tags) SELECT ...` (or `VALUES('rebuild')`), never `NOT IN (SELECT rowid FROM posts_fts)`. Bare `SELECT` / `COUNT(*)` / `LIMIT 1` on external-content FTS is not an index probe. Every UPDATE/DELETE trigger needs this audit — a working INSERT trigger does not imply the paired UPDATE/DELETE triggers are safe. Greenfield + repair after sync is mandatory for FTS/sync changes.

### Problem: Cache files written directly to their final path get served truncated
**Root Cause:** Streaming writes went straight to the final cache path and hit-checks used `existsSync`; concurrent readers saw in-progress files as complete, and client aborts left permanently truncated files that were served forever.
**Invariant Rule:** Any on-disk cache written from a stream uses atomic write: unique `*.tmp-<uuid>` + `rename` only after the full upstream `end` AND writer `finish`; every abort/error path unlinks the tmp. Hit-check via `stat` (regular file, size > 0), never bare `existsSync`. Every cache needs a size cap + eviction wired into maintenance; unbounded caches are a bug.

### Problem: Zustand derived toggles flip incorrectly under rapid updates
**Root Cause:** Direct captures like `set({ compactMode: !compactMode })` use stale closure values and can race with concurrent updates.
**Invariant Rule:** For every state update derived from previous state, always use functional setters (`set((state) => ({ ... }))`).

### Problem: React Query key drift resets optimistic post state
**Root Cause:** Cache updates used partial keys while active queries used parameterized keys (tags/source/sortOrder), so refreshed data overwrote local viewed/favorited flags.
**Invariant Rule:** Cache write keys must match read keys exactly. For parameterized feeds, use `setQueriesData({ queryKey: <prefix> })` to update all key variants.

### Problem: Viewer cannot resolve posts from cache after list remount
**Root Cause:** `ViewerOrigin -> queryKey` mapping and manual cache writes (`setQueryData`) diverged from page query key composition (missing dimensions such as `source`, `sortOrder`, `rating`, `aiFilter`).
**Invariant Rule:** Query key construction must be isomorphic across page fetch, viewer lookup, queue origin, and cache mutation paths. Any new key dimension (example: `source` in Browse) must be added in one atomic change to: page `useQuery/useInfiniteQuery` key, `ViewerOrigin` shape, viewer key resolver, `openViewer` origin payload/listKey, and every manual cache write key.

### Problem: Migration number collision blocks schema rollout
**Root Cause:** New migration reused an existing tag (`0014`), so target SQL did not apply in runtime migration flow.
**Invariant Rule:** Migration tags must be unique and monotonic; verify `drizzle/meta/_journal.json` entry exists before relying on new columns.

### Problem: New schema columns crash old local databases
**Root Cause:** Runtime logic referenced columns before migration was guaranteed on all user DBs.
**Invariant Rule:** For rolling schema changes, add startup capability checks (e.g. `PRAGMA table_info`) and fallback code paths until migration adoption is complete.

### Problem: Browse viewed state resets for external posts
**Root Cause:** External post write path inserted into `posts` with `artist_id=EXTERNAL_ARTIST_ID` without ensuring placeholder artist existed, causing FK write failures and later state rollback on refetch.
**Invariant Rule:** Every external-post write path (`view`, `favorite`, `shadow insert`) must ensure `EXTERNAL_ARTIST_ID` exists in the same transaction (`onConflictDoNothing`).

### Problem: Delayed-only viewed persistence is lost on fast tab switches
**Root Cause:** Browse relied on delayed viewer timer; request was canceled before DB write, while UI already showed optimistic viewed state.
**Invariant Rule:** Persist viewed state immediately on card click in list pages. Viewer delayed mark can be only a backup path, not primary persistence.

### Problem: Freeform JSON in DB columns locks data to the first DSL shape
**Root Cause:** Smart playlist queries were stored as raw JSON without schema versioning, so parser changes could break old records or misinterpret fields.
**Invariant Rule:** Any JSON-in-column stored as user data MUST include a version column and be parsed only through a versioned resolver, never through raw JSON.parse.

### Problem: Negative cache died with the process while rate-limit failures risked being cached as absent
**Root Cause:** Tag resolve outcomes collapsed to found/miss; confirmed empty API responses lived only in an in-memory Map (TTL), and unresolved failures (429/network) could be confused with not_found if classification stayed binary.
**Invariant Rule:** Cacheable outcomes of external lookups distinguish `not_found` (persist with TTL in the same table as hits) from `unresolved` (do not persist as absence). Never mix the two — mixing permanently corrupts categorization. One source of truth for negative state (SQLite), no split-brain RAM Map alongside it.

### Problem: Raw-SQL maintenance deleted every fresh not_found row within seconds of startup
**Root Cause:** Drizzle `mode: "timestamp"` stores seconds while maintenance DELETE compared `resolved_at` to a `Date.now()`-based millisecond cutoff — seconds are always below that cutoff, so the first tick wiped the entire negative cache.
**Invariant Rule:** Timestamp columns touched by raw SQL use `mode: "timestamp_ms"` with an explicit unit comment in the schema when the column is authored as ms; otherwise raw SQL must match the column's actual unit (`timestamp` = seconds). Any raw-SQL time comparison — DELETE **and** SELECT/aggregations — MUST have a test that writes via the ORM path and asserts against the production query helper, never a hand-copied SQL string alone.

## Security (credentials)

### Problem: API decrypt failure sends ciphertext to Booru APIs
**Root Cause:** Inline `safeStorage.decryptString` catch blocks fell back to `settings.encryptedApiKey` (base64 ciphertext).
**Invariant Rule:** Use `SecureStorage.decrypt()` or `getDecryptedCredentialsFromRecord()`; on failure return `null` or throw `CredentialDecryptionError`. Never pass stored ciphertext to providers or logs as if it were the key.

### Problem: Split-brain encrypt/decrypt after duplicated crypto helpers
**Root Cause:** `lib/crypto.ts` and `services/secure-storage.ts` copied the same safeStorage + test-fallback logic; Settings encrypted via one module while decrypt went through the other.
**Invariant Rule:** Cryptographic helpers exist in one module (`SecureStorage`); duplicating security code is forbidden.

## Security

### Problem: Static CSP tied to specific domains does not scale to multi-provider architecture
**Root Cause:** Security policy duplicated provider-specific domains instead of deriving them from the provider registry.
**Invariant Rule:** CSP directives that enumerate external domains must be computed from the Provider Registry, never hardcoded in Main or Renderer.

## Renderer / Workers

### Problem: Browse media-type filter breaks after worker pass
**Root Cause:** `useWorkerFilteredPosts` remapped worker output with `mediaType: null` and dropped `viewCount` / `lastViewedAt`.
**Invariant Rule:** Worker round-trip must preserve DB fields; infer `mediaType` from `fileUrl` only when the field is absent.

### Problem: Heavy Zod validation blocks UI on large post lists
**Root Cause:** `Zod.parse()` on 10k+ posts in the renderer main thread before `postMessage`.
**Invariant Rule:** Do not validate full post arrays in the renderer thread; trust IPC + worker, or validate inside the worker if required.

### Problem: Worker filter spam on rapid slider changes
**Root Cause:** Every filter keystroke/toggle immediately posted full arrays to the worker.
**Invariant Rule:** Debounce filter config sent to the worker (~250ms); do not debounce `rawPosts` (scroll/load latency).

## Gallery performance

### Problem: Masonry mode degrades to full DOM for all loaded posts
**Root Cause:** CSS `columns` layout is incompatible with Virtuoso virtualization; masonry path renders every loaded post.
**Invariant Rule:** Document and treat masonry as O(n) DOM. Grid mode is O(visible) via VirtuosoGrid. Warn users or cap loaded pages in masonry for large feeds.

## Performance

### Problem: forwardRef factory declared inside render remounts virtualized lists
**Root Cause:** Creating `forwardRef` component types inside component render (or `useMemo`) produces a new React component identity on each render, so React/Virtuoso remounts list internals.
**Invariant Rule:** Define all `forwardRef` component types at module scope only; inside render choose between pre-defined components, never create new component types.

## UI & Styling

### Problem: "Panic mode" implemented with `visibility:hidden` / `opacity` still leaks media in screenshots
**Root Cause:** OS and third-party screen capture tools read the rendered DOM and resource URLs; CSS-hidden nodes often remain in the accessibility/layout tree with `src` intact.
**Invariant Rule:** Panic Mode must **wipe `src` on `img`, `video`, and `source` elements** (and restore from a data attribute if needed), not rely on CSS hiding. Screenshot tools capture rendered DOM, not stylesheet intent.

### Problem: CSS `break-inside-avoid` silently ignored in flex containers
**Root Cause:** `break-inside-avoid` only works with CSS multi-column layout (`columns-N` / `column-count`). In a flex or grid container it has no effect, but browsers don't warn. Masonry implementations that mix flex + break-inside appear to "work" superficially but produce a single-column list.
**Invariant Rule:** Masonry layouts must use CSS columns explicitly (`columns-2 md:columns-3 ...`) or a bin-packing library (e.g. `masonic`). Combining virtualization with CSS-columns masonry is incompatible; choose one.

### Problem: Validation errors remain visible after context-changing input updates
**Root Cause:** Error state is persisted independently from form inputs, and no reset is performed when provider/credentials change the validation context.
**Invariant Rule:** Reset related error state on any input that changes validation context (e.g. provider select, credential fields) to avoid stale feedback.

## Testing

### Problem: Dual-ABI test setup masks Electron-vs-Node native module incompatibilities
**Root Cause:** When tests rebuild better-sqlite3 against Node.js ABI, they don't execute under Electron's runtime. Edge cases that manifest only under Electron's event loop, WAL semantics, or sandbox behavior pass tests but fail in production.
**Invariant Rule:** Integration tests involving native modules (better-sqlite3) should ideally run inside Electron via Playwright/electron-vitest. If staying with dual-ABI for speed, document the gap explicitly and add end-to-end Electron tests for critical DB paths.

### Problem: `npm run dev` fails with better-sqlite3 NODE_MODULE_VERSION mismatch after running tests
**Root Cause:** Direct `vitest` / `npx vitest` bypasses npm `pretest`/`posttest` hooks that run `db:rebuild:node` before tests and `db:rebuild` (Electron ABI) after — the native module stays on the Node ABI and Electron cannot load it.
**Invariant Rule:** Run tests only via `npm test` / `npm run test:run` / `npm run test:watch` (and their derivatives). Direct `vitest` / `npx vitest` is forbidden unless `db:rebuild:node` is run before and `db:rebuild` after, manually. For a single file: `npm test -- <path>`.

## Architecture & Agent Workflow

### Problem: Unused infrastructure (i18n with a single locale)
**Root Cause:** i18next/react-i18next were added "for growth" with only `en`, while much UI already used hardcoded English and several `t()` keys never existed in `translation.json`.
**Invariant Rule:** Infrastructure layers are added only under a confirmed product requirement; speculative layers are removed. The app is English-only — user-facing strings are inline literals or local constants (3+ uses), not an i18n stack.

### Problem: Agent reports a finished branch that does not exist on remote (or under-reports the diff)
**Root Cause:** Chat "готово" / checkpoint text is not bound to a verifiable git artifact; planned branch names can be remembered and later treated as done without `checkout -b`, commit, or push. Separately, completion reports often list only the prompt's "затронутые файлы" and omit same-task doc-sync / wiring, so reviewers miss real surface area until the PR diff.
**Invariant Rule:** Definition of Done for any Cursor feature prompt = branch **pushed** to origin **and** the final report includes:
1. Literal output of `git log origin/<branch> -1 --oneline`
2. Literal output of `git status -sb` (or the `git push` result showing the remote ref)
3. **Full actual diff inventory** — every path touched (e.g. `git diff --name-only origin/<base>...HEAD`), not only the prompt's planned file list. Doc-sync and incidental wiring count; call them out explicitly.
A report without (1)–(3) is an **incomplete task**. Do not claim a branch "landed" from memory, conversation summary, or docs narrative — verify with `git ls-remote --heads origin <branch>` / code criteria.

### Problem: Part of a prompt batch was never started, and the gap went unnoticed
**Root Cause:** N prompts issued into chat with no dispatcher-side status tracking; execution began mid-queue, the two skipped P0 prompts left no git trace, and later doc narrative ("video-cache through i18n") fabricated a memory of a full run.
**Invariant Rule:** Every prompt batch is registered as a tracking table in `docs/roadmap.md` (branch -> PR -> status: issued / started / merged / cancelled). A batch is closed only when every row is `merged` or explicitly `cancelled` with a reason. "A prompt exists in chat" is not a status. Narrative text must never contradict the table.

### Problem: Custom DI containers are a YAGNI violation for small projects
**Root Cause:** A full IoC-style abstraction (cycle detection, factory theater) was introduced without automatic wiring or scopes; instance-Map `resolve` never runs user code, so circular-dependency stacks are dead.
**Invariant Rule:** Prefer a slim typed instance registry (`Container` + `DI_TOKENS`, keyed by `token.id`). No cycle detection without lazy factories. Use a real IoC container only when automatic wiring or scope management is actually needed.

### Problem: Background API consumers burned the budget for user actions, and 429 state lived in one consumer
**Root Cause:** Shared `ProviderThrottle` had no priorities (FIFO/racing sleeps); tag-resolve kept `globalRateLimitUntilMs` locally so Sync/Browse ignored an already-known host 429.
**Invariant Rule:** A shared API budget has exactly two priorities (`user` / `background`) and one circuit-breaker per host that every consumer writes and reads. Local copies of rate-limit state are forbidden (same split-brain class as duplicated crypto helpers).

### Problem: Re-opening the window stacks duplicate `before-quit` listeners
**Root Cause:** `app.on("before-quit", …)` was registered inside `initializeAppAndWindow()`, which tray Show/click/`activate` can call again after the window was destroyed.
**Invariant Rule:** Register process-lifetime Electron listeners (`before-quit`, CSP setup flags, etc.) once at module scope (or behind a one-shot guard). Window recreation may re-run IPC setup (`removeHandler` first) but must not re-bind app-level quit handlers.
