## ⚠️ Отказ от ответственности и оценка рисков

Этот проект является **неофициальным** и **не аффилирован** ни с каким внешним веб-сайтом или компанией.

-   **Риск контента:** Приложение **не** размещает, не распространяет и не включает в себя какие-либо медиафайлы. Весь контент загружается напрямую из API или CDN оригинального веб-сайта. Пользователи несут ответственность за соблюдение местных законов в отношении NSFW контента и Условий использования (ToS) API целевого веб-сайта.
-   **Риск API (опрос):** Основные сервисы реализованы со строгими механизмами **экспоненциальной задержки (Exponential Backoff)** и **ограничения частоты запросов (Rate Limiting)**, чтобы минимизировать риск блокировки IP/ключа из-за злоупотребления поведением опроса.
-   **Позиция безопасности:** Приложение настроено с обязательным усилением безопасности Electron (Context Isolation, Preload Scripts) для предотвращения любого потенциального удаленного выполнения кода (RCE) через Renderer Process.

## 🏗️ Обзор архитектуры и технологический стек

Приложение придерживается строгой модели **разделения ответственности (SoC)**:

### 1. Core Services (Мозг — Electron Main Process)

Это безопасная среда Node.js. Она обрабатывает весь ввод/вывод, персистентность и секреты.

-   **Десктопная среда выполнения:** **Electron** (выбран из-за контроля `BrowserView`/`Webview` для поддержки инъекций DOM).
-   **База данных:** **SQLite** (через драйвер `better-sqlite3`) с прямым синхронным доступом в Main Process. WAL mode включен для одновременного чтения.
-   **Слой данных:** **Drizzle ORM** (TypeScript-безопасность типов для запросов, "сырые" SQL-метки времени в миллисекундах).
-   **Безопасность:** **Secure Storage** с использованием API Electron `safeStorage` для шифрования учетных данных API в состоянии покоя.
-   **API:** Пользовательская обертка на базе `axios` с логикой повторных попыток и задержки.
-   **Фоновые задачи:** Таймеры Node.js и асинхронные операции.

### 2. Renderer (Лицо — UI Process)

Это изолированная среда браузера. Она отвечает за представление.

-   **Фронтенд:** **React + TypeScript**
-   **Стилизация:** **Tailwind CSS + shadcn/ui** (современный UI, хорошая базовая доступность A11y).
-   **Управление State:** **Zustand** (минималистичный слой State, соответствует принципам KISS/YAGNI).
-   **Получение данных:** **TanStack Query (React Query)** (кэширование, состояния загрузки, граница API).

### 3. Граница безопасности (Привратник)

-   **Архитектура IPC:** Контроллер-ориентированные обработчики IPC с `BaseController` для централизованной обработки ошибок и валидации. Типобезопасная инъекция зависимостей через DI Container.
-   **IPC Bridge:** Строго типизированный интерфейс TypeScript (`bridge.ts`), используемый Renderer для связи с Main Process.
-   **Безопасность:** **Context Isolation** принудительно применяется глобально; нет прямого доступа Node.js из Renderer.
-   **Шифрование:** Учетные данные API шифруются с использованием API Electron `safeStorage`. Расшифровка происходит только в Main Process, когда это необходимо для вызовов API.
-   **Шаблон провайдера:** Поддержка нескольких Booru через интерфейс `IBooruProvider`. Текущие реализации: Rule34.xxx, Gelbooru.

**📖 Подробную информацию об архитектуре см. в [Документации по архитектуре](./docs/architecture.md).**

## 📐 Структура продукта

Приложение организовано в следующие основные разделы, доступные через боковую панель:

-   **Обновления (Подписки)** — Просмотр новых постов от отслеживаемых художников и подписок на Tag.
-   **Просмотр (Все посты)** — Просмотр всех кэшированных постов с расширенной фильтрацией и поиском.
-   **Избранное (Избранное аккаунта)** — Доступ к избранным записям вашего аккаунта, синхронизированным с Booru.
-   **Плейлисты (Коллекции)** — Создание и управление курированными коллекциями постов.
-   **Отслеживаемые (Управление художниками/Tags)** — Управление отслеживаемыми художниками, Tags и подписками.
-   **Настройки** — Настройка поведения синхронизации, лимитов хранения, безопасности и обслуживания базы данных.

## 🎨 Основные принципы UX

### Глобальная верхняя панель

Унифицированная верхняя панель появляется на всех страницах контента, предоставляя:

-   **Поиск** — Быстрый поиск по постам, Tags и художникам.
-   **Фильтры** — Рейтинг, тип медиа, Tags, диапазон дат.
-   **Сортировка** — Сортировка по дате добавления, дате публикации, рейтингу и т.д.
-   **Переключение вида** — Переключение между сеткой, списком и масонской раскладкой.
-   **Статус синхронизации** — Индикатор прогресса синхронизации в реальном времени с меткой времени последней синхронизации.

### Опыт просмотра

Полноэкранный просмотрщик обеспечивает отлаженный опыт просмотра медиа:

-   **Полноэкранный режим** — Иммерсивный просмотр с автоскрытием элементов управления.
-   **Навигация** — Клавиши со стрелками (←/→) для предыдущего/следующего поста.
-   **Горячие клавиши:**
    -   `Esc` — Закрыть просмотрщик.
    -   `←/→` — Навигация между постами.
    -   `F` — Переключить избранное.
    -   `V` — Отметить как просмотренное.
    -   `T` — Переключить панель Tag.
-   **Автоскрытие панелей** — Верхняя и нижняя панели автоматически скрываются после бездействия.
-   **Панель Tag** — Правая выдвижная панель (Slide-over) с кликабельными Tags:
    -   Нажмите на Tag, чтобы добавить фильтр (`+tag`).
    -   Нажмите правой кнопкой мыши или клавишу-модификатор, чтобы исключить (`-tag`).
    -   Визуальные индикаторы активных фильтров.

### Прогрессивная загрузка изображений

Оптимизированная стратегия загрузки изображений для производительности:

-   **Preview URL** — Размытое превью низкого разрешения (мгновенное отображение).
-   **Sample URL** — Образец среднего разрешения (загружается в галерее).
-   **File URL** — Оригинал в полном разрешении (загружается только в просмотрщике).

Это обеспечивает быструю начальную загрузку страниц при сохранении высокого качества просмотра.

### Карточки галереи

Карточки постов в галереях включают информативные наложения:

-   **Значок "Просмотрено"** — Индикатор для уже просмотренных постов.
-   **Значок "Избранное"** — Звездочка для избранных постов.
-   **Значок "Рейтинг"** — Визуальный индикатор (Safe/Questionable/Explicit).
-   **Значок "Тип медиа"** — Значок, указывающий на изображение или видеоконтент.

## 🔄 Синхронизация и фоновые процессы

### Автоматическая синхронизация при запуске

Автоматическая синхронизация при запуске приложения:

-   **Настройка переключателя** — Включение/отключение автосинхронизации в Настройках.
-   **Фоновое выполнение** — Синхронизация выполняется в фоновом режиме, не блокируя UI.
-   **Индикаторы прогресса** — Статус синхронизации в реальном времени в верхней панели.

### Периодическая синхронизация

Непрерывная синхронизация, пока приложение запущено:

-   **Настраиваемый интервал** — Установка частоты синхронизации в Настройках (например, каждые 30 минут).
-   **Умное ограничение частоты запросов** — Предотвращает спам API с интеллектуальной задержкой.
-   **Статус последней синхронизации** — Отображение метки времени последней успешной синхронизации.
-   **Уважительный опрос** — Реализует экспоненциальную задержку и соблюдает ограничения API.

## ⚙️ Настройки

### Настройки синхронизации

-   **Автосинхронизация при запуске** — Включение автоматической синхронизации при запуске приложения.
-   **Интервал периодической синхронизации** — Настройка частоты проверки новых постов.
-   **Ограничение частоты запросов** — Настройка задержек между запросами API.

### Хранилище и кэш

-   **Лимит кэша** — Установка максимального размера кэша (изображения превью/образцов).
-   **Очистить кэш** — Опция ручной очистки кэша.
-   **Использование хранилища** — Отображение текущего размера кэша и размера базы данных.

### Безопасность

-   **Хранение API Key** — Безопасное хранение с использованием API Electron `safeStorage`.
    -   API Keys **никогда** не отправляются в Renderer Process.
    -   Шифруются в состоянии покоя с использованием связки ключей платформы (Windows Credential Manager, macOS Keychain, Linux libsecret).
    -   Расшифровка происходит только в Main Process, когда это необходимо для вызовов API.
-   **Модель угроз** — Украденный файл базы данных не раскрывает API Key в открытом виде.

### Управление базой данных

-   **Резервное копирование и восстановление** — Создание резервных копий с отметками времени и восстановление из файлов резервных копий.
-   **Проверка целостности** — Запуск проверки целостности базы данных (`PRAGMA integrity_check`).
-   **Vacuum/Сжатие** — Оптимизация размера файла базы данных и производительности.
-   **Обслуживание** — Операции обслуживания базы данных используют последовательную очередь для предотвращения состояний гонки (неблокирующие).

Приложение стабильно и готово к производству (v4.0.0) со следующими реализованными функциями:

-   ✅ **Версия Electron:** 39.2.7 с последними функциями безопасности.

-   ✅ **Архитектура тестирования:** Унифицированная настройка тестирования с Vitest для Unit/Integration тестов, Playwright для E2E тестов.
-   ✅ **Поддержка двойного ABI:** Автоматическое переключение между Node.js и Electron ABI для `better-sqlite3` во время тестирования.
-   ⚠️ **Статус HMR:** Renderer Process имеет полную поддержку HMR. Main Process требует ручного перезапуска (без автоперезапуска при изменении файлов).

### База данных и схема

-   ✅ **Схема:** Три основные таблицы (`artists`, `posts`, `settings`) с правильными связями.
-   ✅ **Миграции:** Полностью функциональная система миграций с использованием `drizzle-kit` с идемпотентной обработкой миграций.
-   ✅ **Поддержка типов медиа:** Столбец `media_type` в таблице `posts` для эффективной фильтрации изображений/видео (`image`, `video`).
-   ✅ **Индексы:** Оптимизированные индексы по `artistId`, `isViewed`, `publishedAt`, `isFavorited`, `lastChecked`, `createdAt`, `mediaType`.
-   ✅ **Составные индексы:** Составные индексы по `(artist_id, rating, is_viewed)` и `(artist_id, media_type)` для оптимизированных запросов с фильтрацией по нескольким столбцам.
-   ✅ **Полнотекстовый поиск FTS5:** Виртуальная таблица FTS5 `posts_fts` с токенизатором `unicode61` для быстрого поиска по Tags.
-   ✅ **Поддержка провайдеров:** Поддержка нескольких Booru с полем `provider` в таблице artists (rule34, gelbooru).
-   ✅ **Типы художников:** Поддержка типов `tag`, `uploader` и `query`.

### Безопасность и надежность

-   ✅ **Безопасное хранение:** Учетные данные API шифруются с использованием API Electron `safeStorage` (Windows Credential Manager, macOS Keychain, Linux libsecret). Учетные данные шифруются в состоянии покоя, расшифровка происходит только в Main Process.
-   ✅ **Резервное копирование/восстановление базы данных:** Реализована функциональность ручного резервного копирования и восстановления с проверкой целостности. Создание резервных копий с отметками времени и восстановление из файлов.
-   ✅ **Проверка ввода:** Валидация Zod реализована для каждого обработчика IPC через `BaseController`.
-   ✅ **Context Isolation:** Включен глобально с режимом sandbox для максимальной безопасности.
-   ✅ **CSP (Content Security Policy):** Строгий CSP в production, ослабленный для разработки (поддержка HMR).
-   ✅ **Портативный режим:** Полностью реализован — автоматически обнаруживает портативный режим и использует папку `data/`.
-   ✅ **Возрастной барьер:** Реализован компонент возрастного барьера с юридическим подтверждением (`confirmLegal` методом).

### Целостность данных и синхронизация

-   ✅ **Нормализация Tag:** Вводы типа "tag (123)" автоматически преобразуются в "tag" перед сохранением/синхронизацией.
-   ✅ **Служба синхронизации:** Правильно обрабатывает `ON CONFLICT` и заполняет галерею с правильной логикой upsert.
-   ✅ **Обработка меток времени:** Все метки времени используют Drizzle timestamp mode с точной миллисекундной точностью.
-   ✅ **Шаблон провайдера:** Поддержка нескольких Booru через интерфейс `IBooruProvider` (Rule34, Gelbooru).
-   ✅ **Ограничение частоты запросов:** Интеллектуальное ограничение частоты запросов с задержкой 1,5 с между художниками, 0,5 с между страницами.
-   ⚠️ **Меры против ботов:** Используются статические строки User-Agent, фиксированные задержки (1,5 с/0,5 с), но без рандомизации или ротации.

### UI/UX

-   ✅ **Прогрессивная загрузка изображений:** 3-слойная система (Preview → Sample → Original) для мгновенного просмотра.
-   ✅ **Виртуализация:** `react-virtuoso` реализован для эффективного рендеринга больших списков.
-   ✅ **Функциональность поиска:** Локальный поиск художников, удаленный поиск Tags через Booru API автозаполнения и прямой поиск Booru (`searchBooru` метод) с разрешением Tag (`resolveTags`, `resolveCharacterTags`, `resolveCopyrightTags`, `resolveTagsByType`).
-   ✅ **Навигация по боковой панели:** Постоянная боковая панель с основными разделами навигации (Updates, Browse, Favorites, Tracked, Settings).
-   ✅ **Глобальная верхняя панель:** Унифицированная верхняя панель с поиском, фильтрами, элементами управления сортировкой и переключением вида.
-   ✅ **Расширенная фильтрация:** Фильтрация по AI-сгенерированным Tags, типу медиа (image/video), источнику (all/favorites/subscriptions) и рейтингу.
-   ✅ **Сортировка:** Сортировка по дате добавления, дате публикации и рейтингу (по возрастанию/убыванию).
-   ✅ **Режимы просмотра:** Варианты сетки и масонской раскладки с адаптивным дизайном.
-   ✅ **Полноэкранный просмотрщик:** Иммерсивный просмотрщик с горячими клавишами, загрузкой, избранным и управлением Tags.
-   ✅ **Поддержка видео:** Поддерживаются видеоформаты `.mp4`, `.webm`, `.mov`, `.avi`, `.mkv`, `.flv`, `.wmv`, `.m4v` с использованием нативного элемента `<video>`.
-   ✅ **Менеджер загрузок:** Загрузка файлов в полном разрешении с отслеживанием прогресса и управлением очередью.
-   ✅ **Система избранного:** Полная реализация с полем базы данных `isFavorited`, функцией переключения и горячими клавишами.
-   ✅ **Элементы управления резервным копированием:** UI Component для создания и восстановления резервных копий базы данных с проверками целостности.
-   ✅ **Проверка учетных данных:** Проверка учетных данных API перед сохранением и во время операций синхронизации.
-   ✅ **Компонент возрастного барьера:** Полностью реализован с юридическим подтверждением (компонент `AgeGate.tsx` и метод IPC `confirmLegal`).
-   ✅ **Content Security Policy:** Строгий CSP с поддержкой медиаисточников Rule34.xxx и Gelbooru.com.
-   ⏳ **Безопасный режим/NSFW фильтр:** Схема базы данных включает поле `isSafeMode`, но логика размытия пока не реализована в UI Components.

1.  **Получите учетные данные API:**

    -   Посетите https://rule34.xxx/index.php?page=account&s=options

    -   Запустите приложение.

## ⚙️ Настройка для разработки

Этот проект использует **electron-vite** в качестве инструмента сборки как для Electron Main, так и для Renderer процессов, обеспечивая оптимальную производительность сборки.

### Предварительные требования

-   **Node.js:** v18 или выше
-   **npm:** v9 или выше (или yarn)
-   **Git:** Для контроля версий

### Установка

```bash
# Клонировать репозиторий
git clone https://github.com/KazeKaze93/ruledesk.git
cd ruledesk

# Установить зависимости
npm install

# Запустить приложение в режиме разработки
# Это запускает dev-сервер Vite для Renderer и запускает Electron Main Process.
npm run dev
```

### Конфигурация

Приложение хранит конфигурацию в базе данных SQLite:

-   **Учетные данные API:** Надежно хранятся с шифрованием с использованием API Electron `safeStorage`. API Keys шифруются в состоянии покоя и расшифровываются только в Main Process, когда это необходимо для вызовов API.
-   **Расположение базы данных:**
    -   **Портативный режим:** При запуске из портативного исполняемого файла база данных хранится в папке `data/` рядом с исполняемым файлом.
    -   **Стандартный режим:** Каталог пользовательских данных Electron (управляется автоматически).
        -   Windows: `%APPDATA%/RuleDesk/metadata.db`
        -   macOS: `~/Library/Application Support/RuleDesk/metadata.db`
        -   Linux: `~/.config/RuleDesk/metadata.db`
-   **Архитектура базы данных:** Прямой синхронный доступ через `better-sqlite3` с WAL mode для одновременного чтения.
-   **Переменные среды не требуются:** Вся конфигурация осуществляется через UI.

### Сборка бинарного файла

Для упаковки приложения для распространения:

```bash
# Сборка для текущей платформы
npm run build

# Упаковка с electron-builder (после сборки)
npm run dist
# Или используйте electron-builder напрямую:
npx electron-builder
```

Собранные бинарные файлы будут доступны в каталоге `release/`. Точное местоположение вывода может варьироваться в зависимости от вашей конфигурации Electron builder.

**Целевые сборки:**

-   **Windows:** Установщик NSIS и портативный исполняемый файл (x64).
-   **macOS:** Пакет DMG.
-   **Linux:** AppImage.

### Тестирование

Проект использует **Vitest** для Unit и Integration тестов, и **Playwright** для E2E тестов.

```bash
# Запуск всех тестов (автоматически пересобирает better-sqlite3 для Node.js, затем пересобирает для Electron после)
npm test

# Запуск тестов в режиме отслеживания изменений
npm run test:watch

# Запуск только интеграционных тестов (автономный, автоматически пересобирает для Node.js)
npm run test:integration

# Запуск интеграционных тестов в режиме отслеживания изменений (для TDD)
npm run test:integration:watch

# Запуск E2E тестов
npm run test:e2e

# Генерация отчета о покрытии кода
npm run test:coverage
```

**Архитектура тестирования:**

-   **Unit Tests:** Расположены в `tests/unit/` — Тестирование отдельных Components, hooks и утилит.
-   **Integration Tests:** Расположены в `tests/integration/` — Тестирование контроллеров IPC и сервисов с реальной базой данных.
-   **E2E Tests:** Расположены в `tests/e2e/` — Тестирование полных пользовательских рабочих процессов с Playwright.

**Поддержка двойного ABI:**

Настройка тестирования автоматически обрабатывает переключение между Node.js и Electron ABI для `better-sqlite3`:
-   `pretest` hook пересобирает для Node.js перед тестами.
-   `posttest` hook пересобирает для Electron после тестов.
-   Это обеспечивает бесперебойную работу `npm test` и немедленную работу `npm run dev` после.

### Миграции

Если вы модифицируете схему базы данных (`src/main/db/schema.ts`):

```bash
# Сгенерировать миграцию из изменений схемы
npm run db:generate

# Запустить миграции вручную (миграции также запускаются автоматически при запуске)
npm run db:migrate

# Открыть Drizzle Studio для проверки базы данных
npm run db:studio
```

**Примечание:** Миграции запускаются автоматически при запуске приложения. Путь миграции автоматически определяется в зависимости от того, упаковано ли приложение или находится в режиме разработки.

**Оптимизация производительности:**

-   **Полнотекстовый поиск FTS5:** Быстрый поиск по Tags с использованием виртуальной таблицы SQLite FTS5 с токенизатором `unicode61`.
-   **Составные индексы:** Оптимизированные индексы для общих комбинаций фильтров (художник + рейтинг + статус просмотра).
-   **Внешние таблицы контента:** FTS5 использует внешний контент для предотвращения дублирования данных и экономии места для хранения.

-   **Разработка:** База данных хранится в каталоге пользовательских данных Electron.
-   **Production (Стандартный):** Каталог пользовательских данных Electron.
-   **Production (Портативный):** Папка `data/` рядом с исполняемым файлом.
