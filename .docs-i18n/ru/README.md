## ⚠️ Отказ от ответственности и оценка рисков

Этот проект **неофициальный** и **не аффилирован** с каким-либо внешним веб-сайтом или компанией.

-   **Риск контента:** Приложение **не** размещает, не распространяет и не включает в себя медиаконтент. Весь контент загружается напрямую через API или CDN оригинального веб-сайта. Пользователи несут ответственность за соблюдение местного законодательства относительно контента NSFW и Условий использования API (ToS) целевого веб-сайта.
-   **Риск API (опрос):** Основные службы реализованы со строгими механизмами **экспоненциальной задержки** (Exponential Backoff) и **ограничения частоты запросов** (Rate Limiting) для минимизации риска блокировки IP/ключа из-за злоупотребления опросом.
-   **Позиция безопасности:** Приложение настроено с обязательными мерами усиления безопасности Electron (Context Isolation, Preload Scripts) для предотвращения любого потенциального удаленного выполнения кода (RCE) через Renderer Process.

## 🏗️ Обзор архитектуры и технологический стек

Приложение придерживается строгой модели **разделения ответственности (SoC)**:

### 1. Core Services (Мозг — Electron Main Process)

Это безопасная среда Node.js. Она обрабатывает все операции ввода-вывода, сохранение данных и секреты.

-   **Среда выполнения для десктопа:** **Electron** (выбран за управление `BrowserView`/`Webview` для поддержки внедрения DOM).
-   **База данных:** **SQLite** (через драйвер `better-sqlite3`) с прямым синхронным доступом в Main Process. Режим WAL включен для одновременного чтения.
-   **Слой данных:** **Drizzle ORM** (TypeScript типобезопасность для запросов, сырые SQL временные метки в миллисекундах).
-   **Безопасность:** **Безопасное хранилище** с использованием API `safeStorage` Electron для шифрования учетных данных API в состоянии покоя.
-   **API:** Пользовательская обертка на основе `axios` с логикой повторных попыток и экспоненциальной задержки.
-   **Фоновые задачи:** Таймеры Node.js и асинхронные операции.

### 2. Renderer (Лицо — UI Process)

Это изолированная (sandboxed) браузерная среда. Она отвечает за представление.

-   **Фронтенд:** **React + TypeScript**
-   **Стилизация:** **Tailwind CSS + shadcn/ui** (современный UI, хорошая базовая доступность A11y).
-   **Управление состоянием:** **Zustand** (минималистичный слой State, соответствует принципам KISS/YAGNI).
-   **Получение данных:** **TanStack Query (React Query)** (кэширование, состояния загрузки, граница API).

### 3. Граница безопасности (Привратник)

-   **Архитектура IPC:** IPC-обработчики на основе контроллеров с `BaseController` для централизованной обработки ошибок и валидации. Типобезопасная инъекция зависимостей через DI Container.
-   **IPC Bridge:** Строго типизированный TypeScript интерфейс (`bridge.ts`), используемый Renderer для связи с Main Process.
-   **Безопасность:** **Context Isolation** применяется глобально; нет прямого доступа Node.js из Renderer.
-   **Шифрование:** Учетные данные API шифруются с использованием API `safeStorage` Electron. Расшифровка происходит только в Main Process, когда это необходимо для вызовов API.
-   **Шаблон провайдера:** Поддержка нескольких Booru через интерфейс `IBooruProvider`. Текущие реализации: Rule34.xxx, Gelbooru.

**📖 Подробную информацию об архитектуре см. в [документации по архитектуре](./docs/architecture.md).**

## 📐 Структура продукта

Приложение организовано в следующие основные разделы, доступные через боковую панель:

-   **Обновления (Подписки)** — Просмотр новых публикаций от отслеживаемых авторов и подписок на Tag
-   **Просмотр (Все публикации)** — Просмотр всех кэшированных публикаций с расширенной фильтрацией и поиском
-   **Избранное (Избранное аккаунта)** — Доступ к избранным публикациям вашего аккаунта, синхронизированным с Booru
-   **Отслеживаемое (Управление авторами/Tags)** — Управление отслеживаемыми авторами, Tags и подписками
-   **Настройки** — Конфигурирование поведения синхронизации, лимитов хранения, безопасности и обслуживания базы данных

## 🎨 Основные принципы UX

### Глобальная верхняя панель

Унифицированная верхняя панель отображается на всех страницах с контентом и предоставляет:

-   **Поиск** — Быстрый поиск по публикациям, Tags и авторам
-   **Фильтры** — Рейтинг, тип медиа, Tags, диапазон дат
-   **Сортировка** — Сортировка по дате добавления, дате публикации, рейтингу и т. д.
-   **Переключатель вида** — Переключение между макетами сетки, списка и Masonry
-   **Статус синхронизации** — Индикатор хода синхронизации в реальном времени с временной меткой последней синхронизации

### Опыт просмотра

Полноэкранный просмотрщик обеспечивает отполированный опыт просмотра медиа:

-   **Полноэкранный режим** — Иммерсивный просмотр с автоматически скрывающимися элементами управления
-   **Навигация** — Клавиши со стрелками (←/→) для предыдущей/следующей публикации
-   **Горячие клавиши:**
    -   `Esc` — Закрыть просмотрщик
    -   `←/→` — Навигация между публикациями
    -   `F` — Переключить избранное
    -   `V` — Отметить как просмотренное
    -   `T` — Переключить панель Tags
-   **Автоматически скрывающиеся панели** — Верхняя и нижняя панели автоматически скрываются после бездействия
-   **Панель Tags** — Правая выдвижная панель (Slide-over) с кликабельными Tags:
    -   Нажмите на Tag, чтобы добавить фильтр (`+tag`)
    -   Щелкните правой кнопкой мыши или используйте клавишу-модификатор, чтобы исключить (`-tag`)
    -   Визуальные индикаторы активных фильтров

### Прогрессивная загрузка изображений

Оптимизированная стратегия загрузки изображений для повышения производительности:

-   **URL предварительного просмотра** — Размытое предварительное изображение низкого разрешения (мгновенное отображение)
-   **URL образца** — Образец среднего разрешения (загружается в галерее)
-   **URL файла** — Оригинальное изображение полного разрешения (загружается только в просмотрщике)

Это обеспечивает быструю начальную загрузку страниц при сохранении высокого качества просмотра.

### Карточки галереи

Карточки публикаций в представлениях галереи включают информативные наложения:

-   **Значок "Просмотрено"** — Индикатор уже просмотренных публикаций
-   **Значок "Избранное"** — Значок звезды для избранных публикаций
-   **Значок рейтинга** — Визуальный индикатор (Безопасно/Сомнительно/Откровенно)
-   **Значок типа медиа** — Значок, указывающий на изображение или видеоконтент

## 🔄 Синхронизация и фоновые процессы

### Автоматическая синхронизация при запуске

Автоматическая синхронизация при запуске приложения:

-   **Переключатель настройки** — Включение/отключение автоматической синхронизации в Настройках
-   **Фоновое выполнение** — Синхронизация выполняется в фоновом режиме, не блокируя UI
-   **Индикаторы прогресса** — Статус синхронизации в реальном времени на верхней панели

### Периодическая синхронизация

Непрерывная синхронизация во время работы приложения:

-   **Настраиваемый интервал** — Установите частоту синхронизации в Настройках (например, каждые 30 минут)
-   **Интеллектуальное ограничение частоты запросов** — Предотвращает спам API с помощью интеллектуальной экспоненциальной задержки.
-   **Статус последней синхронизации** — Отображение временной метки последней успешной синхронизации
-   **Аккуратный опрос** — Реализует экспоненциальную задержку и соблюдает лимиты API

## ⚙️ Настройки

### Настройки синхронизации

-   **Автоматическая синхронизация при запуске** — Включить/отключить автоматическую синхронизацию при запуске приложения
-   **Интервал периодической синхронизации** — Настройте, как часто проверять наличие новых публикаций
-   **Ограничение частоты запросов** — Настройте задержки между запросами API

### Хранилище и кэш

-   **Лимит кэша** — Установите максимальный размер кэша (изображения предварительного просмотра/образцов)
-   **Очистить кэш** — Опция ручной очистки кэша
-   **Использование хранилища** — Отображение текущего размера кэша и размера базы данных

### Безопасность

-   **Хранение ключей API** — Безопасное хранение с использованием API `safeStorage` Electron
    -   Ключи API **никогда** не отправляются в Renderer Process
    -   Зашифрованы в состоянии покоя с использованием системной связки ключей (Windows Credential Manager, macOS Keychain, Linux libsecret)
    -   Расшифровка происходит только в Main Process при необходимости вызовов API.
-   **Модель угроз** — Украденный файл базы данных не раскрывает ключ API в открытом виде

### Управление базой данных

-   **Резервное копирование и восстановление** — Создавайте резервные копии с временными метками и восстанавливайте данные из файлов резервных копий
-   **Проверка целостности** — Запуск проверки целостности базы данных (`PRAGMA integrity_check`)
-   **Вакуумирование/Сжатие** — Оптимизация размера файла базы данных и производительности
-   **Обслуживание** — Операции по обслуживанию базы данных используют последовательную очередь для предотвращения состояний гонки (неблокирующие)

## ✅ Текущий статус

Приложение стабильно и готово к производственному использованию со следующими реализованными возможностями:

### Инфраструктура и сборка

-   ✅ **Версия Electron:** 39.2.7 с последними функциями безопасности
-   ✅ **Система сборки:** electron-vite для оптимальной производительности сборки

-   ✅ **Миграции:** Полностью функциональная система миграций с использованием `drizzle-kit`
-   ✅ **Индексы:** Оптимизированные индексы по `artistId`, `isViewed`, `publishedAt`, `isFavorited`, `lastChecked`, `createdAt`
-   ✅ **Составные индексы:** Составной индекс по `(artist_id, rating, is_viewed)` для оптимизированных запросов с многоколоночной фильтрацией
-   ✅ **Полнотекстовый поиск FTS5:** Виртуальная таблица FTS5 `posts_fts` с токенизатором `unicode61` для быстрого поиска Tags
-   ✅ **Поддержка провайдеров:** Поддержка нескольких Booru с полем `provider` в таблице artists (Rule34, Gelbooru)
-   ✅ **Типы авторов:** Поддержка типов `tag`, `uploader` и `query`

### Безопасность и надежность

-   ✅ **Безопасное хранение:** Учетные данные API шифруются с использованием API `safeStorage` Electron (Windows Credential Manager, macOS Keychain, Linux libsecret). Учетные данные зашифрованы в состоянии покоя, расшифровка только в Main Process
-   ✅ **Резервное копирование/Восстановление базы данных:** Реализована функциональность ручного резервного копирования и восстановления с проверками целостности. Создание резервных копий с временными метками и восстановление из файлов
-   ✅ **Валидация ввода:** Валидация Zod реализована для каждого IPC-обработчика через `BaseController`
-   ✅ **Context Isolation:** Включено глобально с режимом песочницы для максимальной безопасности
-   ✅ **CSP (Content Security Policy):** Строгая CSP в производстве, ослабленная для разработки (поддержка HMR)
-   ✅ **Портативный режим:** Полностью реализован — автоматически определяет портативный режим и использует папку `data/`
-   ✅ **Возрастной ценз:** Компонент возрастного ценза реализован с юридическим подтверждением (метод `confirmLegal`)

### Целостность данных и синхронизация

-   ✅ **Нормализация Tag:** Входные данные, такие как "tag (123)", автоматически сокращаются до "tag" перед сохранением/синхронизацией
-   ✅ **Служба синхронизации:** Правильно обрабатывает `ON CONFLICT` и заполняет галерею с корректной логикой upsert
-   ✅ **Обработка временных меток:** Все временные метки используют режим временных меток Drizzle с правильной точностью до миллисекунд
-   ✅ **Шаблон провайдера:** Поддержка нескольких Booru через интерфейс `IBooruProvider` (Rule34, Gelbooru)
-   ✅ **Ограничение частоты запросов:** Интеллектуальное ограничение частоты запросов с задержкой 1,5 с между авторами, 0,5 с между страницами
-   ⚠️ **Меры противодействия ботам:** Используются статические строки User-Agent, фиксированные задержки (1,5 с/0,5 с), но без рандомизации или ротации

### UI/UX

-   ✅ **Прогрессивная загрузка изображений:** 3-уровневая система (Предварительный просмотр → Образец → Оригинал) для мгновенного просмотра
-   ✅ **Виртуализация:** `react-virtuoso` реализован для эффективной отрисовки больших списков
-   ✅ **Функциональность поиска:** Локальный поиск авторов, удаленный поиск Tags через API автозаполнения Booru, и прямой поиск Booru (`searchBooru` метод) с разрешением Tags (`resolveTags`, `resolveCharacterTags`, `resolveCopyrightTags`, `resolveTagsByType`)
-   ✅ **Навигация по боковой панели:** Постоянная боковая панель с основными разделами навигации (Обновления, Просмотр, Избранное, Отслеживаемое, Настройки)
-   ✅ **Глобальная верхняя панель:** Унифицированная верхняя панель с поиском, фильтрами, элементами управления сортировкой и переключателями вида (UI реализован, фильтрация на бэкенде ожидает)
-   ✅ **Полноэкранный просмотрщик:** Иммерсивный просмотрщик с горячими клавишами, загрузкой, избранным и управлением Tags
-   ✅ **Поддержка видео:** Поддерживаются видеоформаты `.mp4` и `.webm` с использованием нативного элемента `<video>`
-   ✅ **Менеджер загрузок:** Загрузка файлов полного разрешения с отслеживанием прогресса и управлением очередью
-   ✅ **Система избранного:** Полная реализация с полем базы данных `isFavorited`, функцией переключения и горячими клавишами
-   ✅ **Элементы управления резервным копированием:** UI Component для создания и восстановления резервных копий базы данных с проверками целостности
-   ✅ **Верификация учетных данных:** Проверка учетных данных API перед сохранением и во время операций синхронизации

## ⚙️ Настройка для разработки

Этот проект использует **electron-vite** в качестве инструмента сборки как для Electron Main Process, так и для Renderer Process, обеспечивая оптимальную производительность сборки.

### Предварительные требования

-   **Node.js:** v18 или выше
-   **npm:** v9 или выше (или yarn)
-   **Git:** Для контроля версий

### Установка

```bash
# Clone the repository
git clone https://github.com/KazeKaze93/ruledesk.git
cd ruledesk

# Install dependencies
npm install

# Start the application in development mode
# This runs the Vite dev server for the Renderer and starts the Electron Main process.
npm run dev
```

### Конфигурация

Приложение хранит конфигурацию в базе данных SQLite:

-   **Учетные данные API:** Надежно хранятся с шифрованием с использованием API `safeStorage` Electron. Ключи API зашифрованы в состоянии покоя и расшифровываются только в Main Process при необходимости вызовов API.
-   **Расположение базы данных:**
    -   **Портативный режим:** Если запуск производится из портативного исполняемого файла, база данных хранится в папке `data/` рядом с исполняемым файлом
    -   **Стандартный режим:** Каталог пользовательских данных Electron (управляется автоматически)
        -   Windows: `%APPDATA%/RuleDesk/metadata.db`
        -   macOS: `~/Library/Application Support/RuleDesk/metadata.db`
        -   Linux: `~/.config/RuleDesk/metadata.db`
-   **Архитектура базы данных:** Прямой синхронный доступ через `better-sqlite3` с режимом WAL для одновременного чтения
-   **Переменные среды не требуются:** Вся конфигурация обрабатывается через UI

### Сборка бинарного файла

Для упаковки приложения для распространения:

```bash
# Build for current platform
npm run build

# Package with electron-builder (after build)
npm run dist
# Or use electron-builder directly:
npx electron-builder
```

Собранные бинарные файлы будут доступны в директории `release/`. Точное местоположение вывода может варьироваться в зависимости от вашей конфигурации Electron builder.

**Целевые платформы сборки:**

-   **Windows:** NSIS-инсталлятор и портативный исполняемый файл (x64)
-   **macOS:** DMG-пакет
-   **Linux:** AppImage

### Проверки качества

Выполните следующие команды, чтобы обеспечить качество кода:

```bash
# Type checking
npm run typecheck

# Run linter to check code style and potential issues
npm run lint

# Run both (validation)
npm run validate
```

## 🛡️ Стандарты качества кода

Этот проект придерживается строгих принципов разработки:

-   **Архитектура:** Принципы SOLID, DRY, KISS, YAGNI
-   **TypeScript:** Строгая типизация, без `any` или небезопасных приведений типов
-   **Обработка ошибок:** Корректная обработка ошибок с описательными сообщениями через `BaseController`
-   **Безопасность:** Включен Context Isolation, режим песочницы, заголовки CSP, нет прямого доступа Node.js из Renderer
-   **База данных:** Типобезопасные запросы через Drizzle ORM, без сырого SQL (за исключением миграций)
-   **UI:** Только Tailwind CSS, без инлайновых стилей, UI Components shadcn/ui, соображения доступности
-   **Логирование:** `electron-log` для всех операций логирования (без `console.log` в производственном коде)
-   **IPC:** Архитектура на основе контроллеров с инъекцией зависимостей

**📖 Подробные рекомендации см. в [Руководстве для контрибьюторов](./docs/contributing.md).**
