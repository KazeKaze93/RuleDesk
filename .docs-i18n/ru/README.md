## ⚠️ Отказ от ответственности и оценка рисков

Этот проект является **неофициальным** и **не аффилирован** с каким-либо внешним веб-сайтом или компанией.

-   **Риск контента:** Приложение **не** размещает, не распространяет и не встраивает медиаконтент. Весь контент загружается напрямую через API или CDN исходного веб-сайта. Пользователи несут ответственность за соблюдение местного законодательства относительно NSFW-контента и Условий использования API (ToS) целевого веб-сайта.
-   **Риск API (опросы):** Core Services реализованы со строгими механизмами **экспоненциальной задержки (Exponential Backoff)** и **ограничения частоты запросов (Rate Limiting)** для минимизации риска блокировок IP/ключей из-за недобросовестного поведения при опросах.
-   **Позиция в области безопасности:** Приложение настроено с обязательным усилением безопасности Electron (Context Isolation, Preload Scripts) для предотвращения любого потенциального удаленного выполнения кода (RCE) через Renderer Process.

## 🏗️ Обзор архитектуры и стек технологий

Приложение придерживается строгой модели **Разделения ответственности (SoC)**:

### 1. Core Services (Мозг – Electron Main Process)

Это безопасная среда Node.js. Она обрабатывает весь ввод-вывод, сохранение данных и секреты.

-   **Среда выполнения для десктопа:** **Electron** (выбран для управления `BrowserView`/`Webview` с целью поддержки внедрения DOM).
-   **База данных:** **SQLite** (через драйвер `better-sqlite3`) с прямым синхронным доступом в Main Process. Режим WAL включен для параллельного чтения.
-   **Слой данных:** **Drizzle ORM** (типобезопасность TypeScript для запросов, отметки времени в миллисекундах в чистом SQL).
-   **Безопасность:** **Безопасное хранение** с использованием API `safeStorage` Electron для шифрования учетных данных API при хранении.
-   **API:** Пользовательский враппер на базе `axios` с логикой повторных попыток и задержки.
-   **Фоновые задачи:** Таймеры Node.js и асинхронные операции.

### 2. Renderer (Лицо – UI Process)

Это изолированная среда браузера. Она отвечает за представление.

-   **Фронтенд:** **React + TypeScript**
-   **Стилизация:** **Tailwind CSS + shadcn/ui** (современный UI, хорошая базовая доступность (A11y)).
-   **Управление состоянием:** **Zustand** (минималистичный слой State, соответствующий принципам KISS/YAGNI).
-   **Получение данных:** **TanStack Query (React Query)** (кеширование, States загрузки, граница API).

### 3. Граница безопасности (Привратник)

-   **Архитектура IPC:** IPC обработчики на основе контроллеров с `BaseController` для централизованной обработки ошибок и валидации. Типобезопасное внедрение зависимостей через DI Container.
-   **IPC Bridge:** Строго типизированный TypeScript интерфейс (`bridge.ts`), используемый Renderer для связи с Main Process.
-   **Безопасность:** **Context Isolation** включена глобально; отсутствие прямого доступа Node.js из Renderer.
-   **Шифрование:** Учетные данные API шифруются с использованием API `safeStorage` Electron. Расшифровка происходит только в Main Process, когда это необходимо для вызовов API.
-   **Паттерн Provider:** Поддержка нескольких Booru через интерфейс `IBooruProvider`. Текущие реализации: Rule34.xxx, Gelbooru.

**📖 Подробную информацию об архитектуре см. в [Документации по архитектуре](./docs/architecture.md).**

## 📐 Структура продукта

Приложение организовано в следующие основные разделы, доступные через боковую панель:

-   **Обновления (Подписки)** – Просмотр новых постов от отслеживаемых художников и подписок по Tag'ам
-   **Просмотр (Все посты)** – Просмотр всех кешированных постов с расширенной фильтрацией и поиском
-   **Избранное (Избранное аккаунта)** – Доступ к избранным постам вашего аккаунта, синхронизированным из Booru
-   **Отслеживаемые (Управление художниками/Tag'ами)** – Управление отслеживаемыми художниками, Tag'ами и подписками
-   **Настройки** – Настройка поведения синхронизации, лимитов хранилища, безопасности и обслуживания базы данных

## 🎨 Основные принципы UX

### Глобальная верхняя панель

Единая верхняя панель отображается на всех страницах контента и предоставляет:

-   **Поиск** – Быстрый поиск по постам, Tag'ам и художникам
-   **Фильтры** – Рейтинг, тип медиа, Tag'и, диапазон дат
-   **Сортировка** – Сортировка по дате добавления, дате публикации, рейтингу и т.д.
-   **Переключатель вида** – Переключение между макетами сетки, списка и масонри
-   **Статус синхронизации** – Индикатор прогресса синхронизации в реальном времени с отметкой времени последней синхронизации

### Опыт просмотра

Полноэкранный просмотрщик обеспечивает отточенный опыт просмотра медиа:

-   **Полноэкранный режим** – Иммерсивный просмотр с автоматически скрывающимися элементами управления
-   **Навигация** – Клавиши со стрелками (←/→) для предыдущего/следующего поста
-   **Горячие клавиши:**
    -   `Esc` – Закрыть просмотрщик
    -   `←/→` – Навигация между постами
    -   `F` – Переключить избранное
    -   `V` – Отметить как просмотренное
    -   `T` – Переключить панель Tag'ов
-   **Автоматически скрывающиеся панели** – Верхняя и нижняя панели автоматически скрываются после бездействия
-   **Панель Tag'ов** – Боковая панель (Slide-over) справа с кликабельными Tag'ами:
    -   Нажмите на Tag, чтобы добавить фильтр (`+tag`)
    -   Щелкните правой кнопкой мыши или используйте клавишу-модификатор, чтобы исключить (`-tag`)
    -   Визуальные индикаторы для активных фильтров

### Прогрессивная загрузка изображений

Оптимизированная стратегия загрузки изображений для повышения производительности:

-   **Preview URL** – Размытое превью низкого разрешения (мгновенное отображение)
-   **Sample URL** – Образец среднего разрешения (загружается в галерее)
-   **File URL** – Оригинал в полном разрешении (загружается только в просмотрщике)

Это обеспечивает быструю первоначальную загрузку страниц при этом поддерживая высокое качество просмотра.

### Карточки галереи

Карточки постов в представлениях галереи включают информативные наложения:

-   **Значок «Просмотрено»** – Индикатор для уже просмотренных постов
-   **Значок «Избранное»** – Звездная иконка для избранных постов
-   **Значок рейтинга** – Визуальный индикатор (Безопасно/Сомнительно/Откровенно)
-   **Значок типа медиа** – Иконка, указывающая на изображение или видеоконтент

## 🔄 Синхронизация и фон

### Автосинхронизация при запуске

Автоматическая синхронизация при запуске приложения:

-   **Переключение настройки** – Включить/отключить автосинхронизацию в Настройках
-   **Выполнение в фоновом режиме** – Синхронизация работает в фоновом режиме, не блокируя UI
-   **Индикаторы прогресса** – Статус синхронизации в реальном времени в верхней панели

### Периодическая синхронизация

Непрерывная синхронизация во время работы приложения:

-   **Настраиваемый интервал** – Настроить частоту синхронизации в Настройках (например, каждые 30 минут)
-   **Интеллектуальное ограничение частоты запросов** – Предотвращает спам API с помощью интеллектуальной задержки
-   **Статус последней синхронизации** – Отображает отметку времени последней успешной синхронизации
-   **Корректный опрос** – Реализует экспоненциальную задержку и соблюдает ограничения API

## ⚙️ Настройки

### Настройки синхронизации

-   **Автосинхронизация при запуске** – Переключение автоматической синхронизации при запуске приложения
-   **Интервал периодической синхронизации** – Настройка частоты проверки новых постов
-   **Ограничение частоты запросов** – Настройка задержек между запросами API

### Хранилище и кеш

-   **Лимит кеша** – Установить максимальный размер кеша (изображения предпросмотра/образцов)
-   **Очистить кеш** – Опция ручной очистки кеша
-   **Использование хранилища** – Отображает текущий размер кеша и размер базы данных

### Безопасность

-   **Хранение API ключей** – Безопасное хранение с использованием API `safeStorage` Electron
    -   Ключи API **никогда** не отправляются в Renderer Process
    -   Зашифрованы при хранении с использованием связки ключей платформы (Windows Credential Manager, macOS Keychain, Linux `libsecret`)
    -   Расшифровка происходит только в Main Process, когда это необходимо для вызовов API
-   **Модель угроз** – Украденный файл базы данных не раскрывает API ключ в открытом виде

### Управление базой данных

-   **Резервное копирование и восстановление** – Создание резервных копий с отметками времени и восстановление из файлов резервных копий
-   **Проверка целостности** – Выполнить проверку целостности базы данных (`PRAGMA integrity_check`)
-   **Сжатие/Компактизация** – Оптимизировать размер файла базы данных и производительность
-   **Обслуживание** – Операции обслуживания базы данных используют последовательную очередь для предотвращения состояний гонки (неблокирующие)

## ✅ Текущий статус

Приложение стабильно и готово к производству (v4.0.0) со следующими реализованными возможностями:

### Инфраструктура и сборка

-   ✅ **Версия Electron:** 39.2.7 с последними функциями безопасности
-   ✅ **Система сборки:** `electron-vite` для оптимальной производительности сборки
-   ✅ **Архитектура базы данных:** Прямой синхронный доступ через `better-sqlite3` в Main Process с режимом WAL для параллельного чтения
-   ✅ **Портативный режим:** Поддержка портативных исполняемых файлов с папкой данных рядом с исполняемым файлом
-   ✅ **Архитектура тестирования:** Унифицированная настройка тестирования с `Vitest` для Unit/Integration тестов, `Playwright` для E2E тестов
-   ✅ **Поддержка двойного ABI:** Автоматическое переключение между Node.js и Electron ABI для `better-sqlite3` во время тестирования
-   ⚠️ **Статус HMR:** Renderer Process имеет полную поддержку HMR. Main Process требует ручного перезапуска (без автоперезапуска при изменениях файлов)

### База данных и схема

-   ✅ **Схема:** Три основные таблицы (`artists`, `posts`, `settings`) с правильными связями
-   ✅ **Миграции:** Полностью функциональная система миграций, использующая `drizzle-kit` с идемпотентной обработкой миграций
-   ✅ **Поддержка типов медиа:** Столбец `media_type` в таблице `posts` для эффективной фильтрации изображений/видео (`image`, `video`)
-   ✅ **Индексы:** Оптимизированные Индексы по `artistId`, `isViewed`, `publishedAt`, `isFavorited`, `lastChecked`, `createdAt`, `mediaType`
-   ✅ **Составные Индексы:** Составные Индексы по `(artist_id, rating, is_viewed)` и `(artist_id, media_type)` для оптимизированных многоколоночных фильтрующих запросов
-   ✅ **Полнотекстовый поиск FTS5:** Виртуальная таблица FTS5 `posts_fts` с токенизатором `unicode61` для быстрого поиска по Tag'ам
-   ✅ **Поддержка провайдеров:** Поддержка нескольких Booru с полем `provider` в таблице artists (Rule34, Gelbooru)
-   ✅ **Типы художников:** Поддержка типов `tag`, `uploader` и `query`

### Безопасность и надежность

-   ✅ **Безопасное хранение:** Учетные данные API зашифрованы с использованием API `safeStorage` Electron (Windows Credential Manager, macOS Keychain, Linux `libsecret`). Учетные данные зашифрованы при хранении, расшифровка происходит только в Main Process
-   ✅ **Резервное копирование/восстановление базы данных:** Реализована функция ручного резервного копирования и восстановления с проверкой целостности. Создание резервных копий с отметками времени и восстановление из файлов
-   ✅ **Валидация ввода:** Валидация `Zod` реализована для каждого IPC обработчика через `BaseController`
-   ✅ **Изоляция контекста:** Включена глобально с режимом песочницы для максимальной безопасности
-   ✅ **CSP (Политика безопасности контента):** Строгий CSP в production, ослабленный для development (поддержка HMR)
-   ✅ **Портативный режим:** Полностью реализовано — автоматически определяет портативный режим и использует папку `data/`
-   ✅ **Возрастное ограничение:** Реализован Component возрастного ограничения с подтверждением юридических условий (`confirmLegal` метод)

### Целостность данных и синхронизация

-   ✅ **Нормализация Tag'ов:** Ввод, например «Tag (123)», автоматически обрезается до «Tag» перед сохранением/синхронизацией
-   ✅ **Сервис синхронизации:** Корректно обрабатывает `ON CONFLICT` и заполняет галерею с использованием правильной логики upsert
-   ✅ **Обработка отметок времени:** Все отметки времени используют режим Drizzle timestamp с точной миллисекундной точностью
-   ✅ **Паттерн Provider:** Поддержка нескольких Booru через интерфейс `IBooruProvider` (Rule34, Gelbooru)
-   ✅ **Ограничение частоты запросов:** Интеллектуальное ограничение частоты запросов с задержкой 1.5 с между художниками, 0.5 с между страницами
-   ⚠️ **Меры по борьбе с ботами:** Используются статические строки User-Agent, фиксированные задержки (1.5 с/0.5 с), но без рандомизации или ротации

### UI/UX

-   ✅ **Прогрессивная загрузка изображений:** 3-уровневая система (Preview → Sample → Original) для мгновенного просмотра
-   ✅ **Виртуализация:** Реализован `react-virtuoso` для эффективной отрисовки больших списков

-   ✅ **Навигация по боковой панели:** Постоянная боковая панель с основными разделами навигации (Обновления, Просмотр, Избранное, Отслеживаемые, Настройки)
-   ✅ **Глобальная верхняя панель:** Единая верхняя панель с поиском, фильтрами, элементами управления сортировкой и переключателями вида
-   ✅ **Расширенная фильтрация:** Фильтрация по AI-сгенерированным Tag'ам, типу медиа (изображение/видео), источнику (все/избранное/подписки) и рейтингу
-   ✅ **Сортировка:** Сортировка по дате добавления, дате публикации и рейтингу (по возрастанию/убыванию)

-   ✅ **Полноэкранный просмотрщик:** Иммерсивный просмотрщик с горячими клавишами, загрузкой, избранным и управлением Tag'ами
-   ✅ **Поддержка видео:** Видеоформаты `.mp4`, `.webm`, `.mov`, `.avi`, `.mkv`, `.flv`, `.wmv`, `.m4v` поддерживаются с помощью нативного элемента `<video>`
-   ✅ **Менеджер загрузок:** Загрузка файлов в полном разрешении с отслеживанием прогресса и управлением очередью
-   ✅ **Система избранного:** Полная реализация с полем базы данных `isFavorited`, функцией переключения и горячими клавишами
-   ✅ **Элементы управления резервным копированием:** UI Component для создания и восстановления резервных копий базы данных с проверкой целостности
-   ✅ **Верификация учетных данных:** Проверка учетных данных API перед сохранением и во время операций синхронизации

    -   Посетите https://rule34.xxx/index.php?page=account&s=options

## ⚙️ Настройка разработки

Этот проект использует **electron-vite** в качестве инструмента сборки как для Electron Main, так и для Renderer процессов, обеспечивая оптимальную производительность сборки.

### Предварительные требования

-   **Node.js:** v18 или выше
-   **npm:** v9 или выше (или yarn)
-   **Git:** Для контроля версий

### Установка

```bash
# Clone the repository
git clone https://github.com/KazeKaze93/ruledesk.git
cd ruledesk

# Install dependencies
npm install

# Start the application in development mode
# This runs the Vite dev server for the Renderer and starts the Electron Main process.
npm run dev
```

### Конфигурация

Приложение хранит конфигурацию в базе данных SQLite:

-   **Учетные данные API:** Безопасно хранятся с шифрованием с использованием API `safeStorage` Electron. Ключи API зашифрованы при хранении и расшифровываются только в Main Process, когда это необходимо для вызовов API.
-   **Расположение базы данных:**
    -   **Портативный режим:** Если запущено из портативного исполняемого файла, база данных хранится в папке `data/` рядом с исполняемым файлом
    -   **Стандартный режим:** Каталог пользовательских данных Electron (автоматически управляется)
        -   Windows: `%APPDATA%/RuleDesk/metadata.db`
        -   macOS: `~/Library/Application Support/RuleDesk/metadata.db`
        -   Linux: `~/.config/RuleDesk/metadata.db`
-   **Архитектура базы данных:** Прямой синхронный доступ через `better-sqlite3` с режимом WAL для параллельного чтения
-   **Переменные окружения не требуются:** Вся конфигурация управляется через UI

### Сборка бинарного файла

Для упаковки приложения для распространения:

```bash
# Build for current platform
npm run build

# Package with electron-builder (after build)
npm run dist
# Or use electron-builder directly:
npx electron-builder
```

Собранные бинарные файлы будут доступны в каталоге `release/`. Точное местоположение вывода может варьироваться в зависимости от вашей конфигурации Electron builder.

**Цели сборки:**

-   **Windows:** Установщик NSIS и портативный исполняемый файл (x64)
-   **macOS:** Пакет DMG
-   **Linux:** AppImage

### Проверки качества

Выполните следующие команды для обеспечения качества кода:

```bash
# Type checking
npm run typecheck

# Run linter to check code style and potential issues
npm run lint

# Run both (validation)
npm run validate
```

### Тестирование

Проект использует **Vitest** для модульных и интеграционных тестов, а также **Playwright** для E2E тестов.

```bash
# Run all tests (automatically rebuilds better-sqlite3 for Node.js, then rebuilds for Electron after)
npm test

# Run tests in watch mode
npm run test:watch

# Run only integration tests (autonomous, rebuilds for Node.js automatically)
npm run test:integration

# Run integration tests in watch mode (for TDD)
npm run test:integration:watch

# Run E2E tests
npm run test:e2e

# Generate coverage report
npm run test:coverage
```

**Архитектура тестирования:**

-   **Модульные тесты:** Расположены в `tests/unit/` – Тестируют отдельные Components, хуки и утилиты
-   **Интеграционные тесты:** Расположены в `tests/integration/` – Тестируют IPC контроллеры и сервисы с реальной базой данных
-   **E2E тесты:** Расположены в `tests/e2e/` – Тестируют полные пользовательские рабочие процессы с `Playwright`

**Поддержка двойного ABI:**

Настройка тестирования автоматически обрабатывает переключение между Node.js и Electron ABI для `better-sqlite3`:
-   Хук `pretest` пересобирает для Node.js перед тестами
-   Хук `posttest` пересобирает для Electron после тестов
-   Это гарантирует бесперебойную работу `npm test` и немедленную работу `npm run dev` после

## ⚙️ Управление базой данных

### Миграции

Если вы изменяете схему базы данных (`src/main/db/schema.ts`):

```bash
# Generate migration from schema changes
npm run db:generate

# Run migrations manually (migrations also run automatically on startup)
npm run db:migrate

# Open Drizzle Studio to inspect database
npm run db:studio
```

**Примечание:** Миграции запускаются автоматически при старте приложения. Путь миграции автоматически определяется в зависимости от того, упаковано ли приложение или находится в режиме разработки.

**Оптимизация производительности:**

-   **Полнотекстовый поиск FTS5:** Быстрый поиск по Tag'ам с использованием виртуальной таблицы SQLite FTS5 с токенизатором `unicode61`
-   **Составные Индексы:** Оптимизированные Индексы для общих комбинаций фильтров (художник + рейтинг + статус просмотра)
-   **Таблицы внешнего контента:** FTS5 использует внешний контент для избежания дублирования данных и экономии места

### Расположение базы данных

-   **Разработка:** База данных хранится в каталоге пользовательских данных Electron
-   **Production (Стандартный):** Каталог пользовательских данных Electron
-   **Production (Портативный):** Папка `data/` рядом с исполняемым файлом

## 🛡️ Стандарты качества кода

Этот проект придерживается строгих принципов разработки:

-   **Архитектура:** Принципы SOLID, DRY, KISS, YAGNI
-   **TypeScript:** Строгая типизация, без `any` или небезопасных приведений
-   **Обработка ошибок:** Правильная обработка ошибок с описательными сообщениями через `BaseController`
-   **Безопасность:** Включена изоляция контекста, режим песочницы, заголовки CSP, отсутствие прямого доступа Node.js из Renderer
-   **База данных:** Типобезопасные запросы через Drizzle ORM, без чистого SQL (кроме миграций)
-   **UI:** Только Tailwind CSS, без инлайн-стилей, shadcn/ui Components, соображения доступности
-   **Логирование:** `electron-log` для всего логирования (без `console.log` в production коде)
-   **IPC:** Архитектура на основе контроллеров с внедрением зависимостей
