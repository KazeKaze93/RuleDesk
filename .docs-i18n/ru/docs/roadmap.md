## 🧭 Переработка навигации и UX

### Навигация в боковой панели

Реализовать постоянную боковую панель с основными разделами навигации:

- **Обновления** — Лента подписок (новые публикации из отслеживаемых источников)
- **Просмотр** — Все публикации с расширенной фильтрацией
- **Избранное** — Избранное аккаунта, синхронизированное с booru
- **Отслеживаемое** — Управление художниками и Tag'ами
- **Настройки** — Конфигурация приложения

### Глобальная верхняя панель

Единая верхняя панель на всех страницах контента:

- **Строка поиска** — Быстрый поиск по публикациям, Tag'ам, художникам
- **Панель фильтров** — Фильтры по рейтингу, типу медиа, Tag'ам, диапазону дат
- **Элементы управления сортировкой** — Сортировка по дате добавления, дате публикации, рейтингу
- **Переключатель режимов просмотра** — Опции сетки, списка, масонской компоновки
- **Статус синхронизации** — Индикатор синхронизации в реальном времени с меткой времени последней синхронизации

### Доработка средства просмотра

Улучшенный полноэкранный просмотр:

- **Автоматическое скрытие панелей** — Верхняя и нижняя панели скрываются после бездействия
- **Панель Tag'ов** — Выдвижная панель справа с кликабельными Tag'ами
  - Нажмите Tag, чтобы добавить фильтр (`+tag`)
  - Правый клик или клавиша-модификатор для исключения (`-tag`)
  - Визуальные индикаторы активных фильтров
- **Подсказки** — Клавиатурные сокращения и подсказки действий
- **Горячие клавиши:**
  - `Esc` — Закрыть средство просмотра
  - `←/→` — Перемещение между публикациями
  - `F` — Переключить избранное
  - `V` — Отметить как просмотренное
  - `T` — Переключить панель Tag'ов

### Наложения на карточках галереи

Карточки публикаций с информативными наложениями:

- **Значок "Просмотрено"** — Индикатор для просмотренных публикаций
- **Значок "Избранное"** — Звезда для избранных публикаций
- **Значок "Рейтинг"** — Визуальный индикатор (Safe/Questionable/Explicit)
- **Значок "Тип медиа"** — Иконка для изображений/видео контента

### Прогрессивная загрузка изображений

Оптимизированная стратегия загрузки:

- **URL-адрес предпросмотра** — Размытый превью низкого разрешения (мгновенное отображение в галерее)
- **URL-адрес образца** — Образец среднего разрешения (загружается в галерее)
- **URL-адрес файла** — Оригинал полного разрешения (загружается только в средстве просмотра)

## 📰 Подписки / Обновления

### Вкладка «Лента»

Единая лента, показывающая все новые публикации:

- **Все новые публикации** — Объединенная лента из всех отслеживаемых источников
- **Фильтры** — Применение фильтров по Tag'ам, рейтингу, типу медиа
- **Бесконечная прокрутка** — Прогрессивная загрузка по мере прокрутки пользователем
- **Отметить как прочитанное** — Пакетное помечание публикаций как просмотренных

### Вкладка «Создатели»

Представление списка/плиток создателей с количеством новых публикаций:

- **Список создателей** — Сетка или список отслеживаемых художников
- **Значок количества новых** — Отображение количества непросмотренных публикаций для каждого создателя
- **Быстрые действия** — Синхронизация, восстановление, просмотр галереи для каждого создателя
- **Фильтры** — Фильтрация создателей по типу (Tag/загрузчик)

### Фильтры

Расширенная фильтрация в разделе обновлений:

- **Фильтры по Tag'ам** — Включение/исключение конкретных Tag'ов
- **Фильтр по рейтингу** — Safe, Questionable, Explicit
- **Фильтр по типу медиа** — Изображения, Видео или оба
- **Диапазон дат** — Фильтрация по дате публикации

## 🛡️ Безопасность и надежность (Усиление)

### Безопасность ключей API

Улучшенная безопасность учетных данных API:

- **Изоляция Renderer Process** — Renderer Process никогда не получает необработанный ключ API
- **Безопасное хранение** — Использование Electron API `safeStorage` (Windows Credential Manager, macOS Keychain, Linux libsecret)
- **Политика AES-GCM** — Шифрование ключей API в покое с использованием шифрования AES-GCM
- **Модель угроз** — Украденный файл базы данных не раскрывает ключ API в открытом виде

**Статус:** ✅ **ЗАВЕРШЕНО:** Ключи API зашифрованы в покое, дешифрование происходит только в Main Process.

### Резервное копирование и целостность базы данных

Комплексная защита базы данных:

- **Система резервного копирования** — Ручные и автоматические резервные копии перед обслуживанием
- **Процесс восстановления** — Восстановление из резервной копии с автоматическим перезапуском
- **Проверка целостности** — Выполнение `PRAGMA integrity_check` и отображение результатов
- **Политика хранения** — Сохранение последних N резервных копий, автоматическая очистка старых резервных копий

**Статус:** ✅ **Фаза 1 ЗАВЕРШЕНА:** Реализовано ручное резервное копирование/восстановление. В будущем: Автоматическое резервное копирование, UI проверки целостности, политика хранения.

### Автоматическое обслуживание

Неблокирующее обслуживание базы данных:

- **Очередь обслуживания** — Все операции обслуживания выполняются последовательно через очередь на основе Promise (`maintenance-queue.ts`)
- **Неблокирующий** — Операции обслуживания не замораживают UI (операции асинхронны)
- **События прогресса** — Обновления прогресса в реальном времени для длительных операций
- **Запланированные запуски** — Автоматическое обслуживание при запуске или через периодические интервалы (планируется)

**Статус:** ✅ **ЗАВЕРШЕНО:** Операции обслуживания базы данных используют последовательную очередь для предотвращения состояний гонки. В будущем: Запланированные запуски обслуживания.

## 🏗️ Архитектурные соображения

### Принципы проектирования

- **KISS и YAGNI:** Keep It Simple, Stupid. You Aren't Gonna Need It. (Делай проще, глупый. Тебе это не понадобится.)
- **SOLID:** Единая ответственность, Открытость/Закрытость, Инверсия зависимостей
- **DRY:** Don't Repeat Yourself (Не повторяйся)
- **Типобезопасность:** Строгий TypeScript, валидация Zod, без типов `any`
- **Разделение ответственности:** Renderer (UI) ↔ Main Process (I/O, БД, API)

### Рекомендации по реализации

- Поддерживать текущие шаблоны схемы (без регрессий)
- Строгая типобезопасность (Zod/TypeScript)
- Разделение ответственности (Renderer Process против Main Process)
- Следовать существующим шаблонам IPC и архитектуре сервисов
- Использовать Drizzle ORM для всех операций с базой данных (без необработанного SQL)
- Корректная обработка ошибок с описательными сообщениями
