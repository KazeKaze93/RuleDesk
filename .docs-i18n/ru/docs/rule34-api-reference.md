## Ключи API

### Запрос ключа API

**URL:** https://rule34.xxx/index.php?page=account&s=options

Перейдите на страницу настроек учетной записи, чтобы запросить ключ API. Вы получите:

- `user_id`: Ваш ID пользователя
- `api_key`: Ваш ключ API для аутентификации

### Ограничения API

Ограничения API могут быть изменены в любое время без предварительного уведомления. Если вашему приложению требуются более высокие лимиты, вы можете запросить неограниченный ключ. Это применимо только для крупных публичных проектов.

**Запрос повышенных лимитов:**

- Для срочных запросов от крупных сайтов/приложений: Создайте тикет в Discord или отправьте сообщение администрации сайта
- Форум для связи с администрацией: https://rule34.xxx/index.php?page=forum&s=view&id=4240

**Важно:** Rule34.xxx оставляет за собой право отключать или отказывать в выдаче любого ключа API по своему усмотрению.

## Условия использования API

При использовании Rule34.xxx API или предоставлении контента с их CDN, вы должны соблюдать следующие условия:

1.  **Без рекламы и платных доступов:** Вы не должны показывать рекламу или использовать платные доступы (paywalls). Это относится ко всем ботам, приложениям и веб-сайтам, использующим API или контент CDN.

2.  **Правило одного ключа API:** Не используйте и не запрашивайте более одного ключа API. Использование нескольких ключей приведет к приостановке действия вашего ключа или учетной записи.

3.  **Приостановка действия ключа:** Нарушение этих условий может привести к немедленной приостановке действия вашего ключа API или учетной записи.

## Эндпоинты

### Посты

#### Список постов

**URL:** `https://api.rule34.xxx/index.php?page=dapi&s=post&q=index`

**Method:** GET

**Параметры:**

| Параметр  | Тип       | Описание                         | Ограничения                                                                        |
| --------- | --------- | -------------------------------- | ---------------------------------------------------------------------------------- |
| `limit`   | integer   | Количество постов для получения  | Жесткое ограничение: 1000 постов за запрос                                          |
| `pid`     | integer   | Номер страницы                   | -                                                                                  |
| `tags`    | string    | Комбинация Tag'ов для поиска    | Любая комбинация Tag'ов, работающая на веб-сайте, включая meta-tags               |
| `cid`     | integer   | ID изменения поста               | Unix-метка времени (могут быть дубликаты при одновременном обновлении)             |
| `id`      | integer   | ID поста                         | -                                                                                  |
| `json`    | integer   | Формат ответа                    | Установите `1` для JSON, пропустите для XML                                        |

**Примечания:**

- Формат ответа по умолчанию — XML, если не указано `json=1`
- Комбинации Tag'ов следуют тем же правилам, что и поиск на веб-сайте
- Информацию о meta-tags см. в шпаргалке

**Пример:**

```
https://api.rule34.xxx/index.php?page=dapi&s=post&q=index&tags=tag1+tag2&limit=100&json=1
```

### Удаленные изображения

#### Список удаленных изображений

**URL:** `https://api.rule34.xxx/index.php?page=dapi&s=post&q=index&deleted=show`

**Method:** GET

**Параметры:**

| Параметр  | Тип       | Описание             | Ограничения                                      |
| --------- | --------- | -------------------- | ------------------------------------------------ |
| `last_id` | integer   | Числовое значение    | Возвращает все, что выше этого числа             |

**Примечания:**

- Для этой конечной точки требуется параметр `deleted=show` в URL
- Используйте `last_id` для пагинации по удаленным изображениям

**Пример:**

```
https://api.rule34.xxx/index.php?page=dapi&s=post&q=index&deleted=show&last_id=12345
```

### Комментарии

#### Список комментариев

**URL:** `https://api.rule34.xxx/index.php?page=dapi&s=comment&q=index`

**Method:** GET

**Параметры:**

| Параметр  | Тип       | Описание              | Ограничения                                         |
| --------- | --------- | --------------------- | --------------------------------------------------- |
| `post_id` | integer   | Номер ID поста        | ID поста, для которого нужно получить комментарии   |

**Пример:**

```
https://api.rule34.xxx/index.php?page=dapi&s=comment&q=index&post_id=123456
```

### Tags

#### Список Tags

**URL:** `https://api.rule34.xxx/index.php?page=dapi&s=tag&q=index`

**Method:** GET

**Параметры:**

| Параметр  | Тип       | Описание                      | Ограничения                                                         |
| --------- | --------- | ----------------------------- | ------------------------------------------------------------------- |
| `id`      | integer   | ID Tag'а в базе данных        | Полезно для получения конкретного Tag'а, если вам уже известен ID   |
| `limit`   | integer   | Количество Tag'ов для получения | Лимит по умолчанию: 100 Tag'ов за запрос                             |

**Пример:**

```
https://api.rule34.xxx/index.php?page=dapi&s=tag&q=index&limit=500
```

### Автозаполнение

#### Автозаполнение Tag'ов

**URL:** `https://api.rule34.xxx/autocomplete.php?q=`

**Method:** GET

**Параметры:**

| Параметр  | Тип       | Описание          | Ограничения                               |
| --------- | --------- | ----------------- | ----------------------------------------- |
| `q`       | string    | Поисковый запрос  | Введите любую букву или неполный Tag      |

**Примечания:**

- Это неофициальная конечная точка, но она доступна для использования
- Некоторые реализации могут использовать автозаполнение с основного сайта; используйте эту конечную точку вместо него
- Возвращает предложения на основе частичного ввода Tag'а

**Пример:**

```
https://api.rule34.xxx/autocomplete.php?q=char
```

## Рекомендации и предостережения

### Ограничение частоты запросов

- Реализуйте экспоненциальную задержку (exponential backoff) для ошибок ограничения частоты запросов
- Соблюдайте лимиты API и избегайте агрессивного опроса
- Отслеживайте частоту ваших запросов, чтобы предотвратить блокировки по IP или ключу
- Рассмотрите возможность кэширования ответов для сокращения количества вызовов API

### Кэширование

- Кэшируйте списки Tag'ов и результаты автозаполнения (они меняются нечасто)
- Кэшируйте метаданные постов для уменьшения избыточных запросов
- Реализуйте соответствующие стратегии инвалидации кэша
- Учитывайте размер кэша и использование памяти

### Соблюдение условий использования

- **Никогда не отображайте рекламу** при использовании API или предоставлении контента CDN
- **Никогда не вводите платные доступы** для контента, доступ к которому осуществляется через API
- **Используйте только один ключ API** на приложение или проект
- Просмотрите и соблюдайте все требования ToS перед развертыванием

### Управление ключами

- Надежно храните ключи API (используйте безопасное хранилище Electron или аналогичное)
- Никогда не добавляйте ключи API в систему контроля версий
- Отслеживайте уведомления о приостановке действия ключа
- Разработайте план на случай отзыва ключа

### Обработка ошибок

- Реализуйте надлежащую обработку ошибок для сбоев сети
- Корректно обрабатывайте ответы об ограничении частоты запросов
- Регистрируйте ошибки для отладки без раскрытия конфиденциальной информации
- Предоставляйте удобные для пользователя сообщения об ошибках

### Вопросы производительности

- Используйте пагинацию (параметр `pid`) для больших наборов результатов
- Соблюдайте ограничение в 1000 постов за запрос
- Рассмотрите параллельные запросы для независимых данных (с учетом ограничения частоты запросов)
- Оптимизируйте запросы по Tag'ам, чтобы уменьшить размер ответа

### Безопасность

- Проверяйте весь пользовательский ввод перед формированием запросов API
- Санитизируйте строки Tag'ов для предотвращения атак внедрения
- Используйте HTTPS для всех запросов API
- Реализуйте обработку тайм-аутов запросов

### Рекомендации по разработке

- Сначала тестируйте с небольшими лимитами, прежде чем масштабировать
- Отслеживайте время ответа API и соответствующим образом корректируйте интервалы опроса
- Реализуйте логику повторных попыток с экспоненциальной задержкой
- Используйте формат JSON (`json=1`) для более легкого парсинга в современных приложениях
- Документируйте шаблоны использования вашего API для устранения неполадок
